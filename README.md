# Stride

A responsive, local project progress workspace built with **Vite 8, React 19, TypeScript 7, shadcn/ui, and Sass**, backed by an Express API and a persistent SQLite database.

## Run

Requires Node.js **24.4+** and npm.

```sh
npm install
npm run dev
```

Open http://127.0.0.1:5173. The API runs on port 3001. A starter workspace is seeded once on first launch; all project and task changes persist in `data/stride.sqlite`.

For an empty workspace, set `SEED_DEMO=false` before starting with a new database. Example:

```sh
DB_PATH=data/my-workspace.sqlite SEED_DEMO=false npm run dev
```

## Features

- Create, edit, and delete projects with owner, description, due date, priority, status, and accent color.
- Add, rename, complete, reopen, and delete tasks. Progress is the percentage of completed tasks; project status is independently managed.
- Workspace summaries, project grid/list views, search, status filters, and a cross-project task view. List view has clickable column headers for name, status, owner, due date, priority, and progress; click again to reverse direction. Projects without a due date remain last in either direction. Sorting is shared with grid view.
- English and Simplified Chinese UI, localized dates, and device-persistent language preferences. User-entered content is preserved in its original language.
- Light, dark, and live system theme support with device-persistent preferences.
- Responsive navigation, keyboard-accessible shadcn dialogs, deletion confirmation, loading/error/empty states.
- SQLite foreign keys, cascading task deletion, input validation, parameterized SQL, and cross-origin mutation rejection.

## Production

```sh
npm run build
npm start
```

Open http://127.0.0.1:3001. Express serves the built frontend and API together. `PORT` and `DB_PATH` are configurable. This is a single-user local application bound to loopback, with no account or collaboration system. Add authentication and a deployment security design before exposing it publicly.

SQLite uses Node's built-in `node:sqlite` module, which emits an experimental-feature warning on Node 24.4. Back up the database with the server stopped, including any SQLite sidecar files if present. Do not delete `data/` unless you intend to reset your projects.

## Verification

```sh
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

API tests use a temporary database and cover CRUD, validation, persistence across reopening, foreign-key deletion, and origin checks. Browser tests use a separate `data/e2e-<timestamp>.sqlite` database with demo seeding disabled and verify the project lifecycle, task progress, search, persisted language/theme, and mobile overflow. Stop any existing dev server before running browser tests.

## Structure

- `src/App.tsx`: workspace views and CRUD interactions
- `src/i18n.ts`: English/Chinese translation resources and preference storage
- `src/styles.scss`: responsive layout, component styling, and theme tokens
- `src/index.css`: Tailwind/shadcn token integration; Sass is compiled separately
- `src/components/ui/`: components generated by the official shadcn CLI
- `src/types.ts`: shared project/task types
- `server/app.ts`: SQLite schema and API
- `server/index.ts`: development/production entrypoint

The dependency lockfile pins the installed versions. No external services or API keys are required.

## Users and ownership

Use **Users** in the sidebar to add or edit workspace users. Tags accept comma-separated values (up to 20 tags per user, 40 characters each). Search matches names and tags; the tag selector filters by an exact tag. These are workspace directory records, not login accounts.

Project forms include a single email-style owner field with removable user chips and searchable suggestions. On each task, click its owner or **Unassigned** to assign, change, or clear the owner. Projects and tasks support multiple owners. Both pickers search names and tags; use arrow keys and Enter to choose, Escape to close suggestions, and Backspace on an empty field to remove the last chip. Owners are linked by user ID, so renaming a user updates their displayed name on assigned projects and tasks.

Existing single-owner assignments are preserved when migrating to multiple owners. Existing databases migrate automatically: distinct nonempty project owner names become users and existing tasks remain unassigned. Projects and task completion are preserved.

## Oxc tooling

```sh
npm run lint       # Oxlint, fail on warnings
npm run lint:fix   # Oxlint automatic fixes
npm run fmt        # Oxfmt formatting
npm run fmt:check  # Oxfmt formatting check
```

Oxc-based linting and formatting are configured in `.oxlintrc.json` and `.oxfmtrc.json`. Vite 8 handles the frontend transformation pipeline; TypeScript 7 checks types. Prettier is not a direct project dependency or command. Oxfmt may use internal compatibility dependencies for non-JavaScript formats.
